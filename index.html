// Operating principles

  1. P/01

    Fewer dependencies, more self-hosting.

    Each dependency is a promise someone else has to keep. Prefer what ships with the platform, and host the rest yourself.

  2. P/02

    No numbers nobody measured.

    A claim like twice as fast needs the experiment behind it. Without one, describe what the system does instead of the improvement.

  3. P/03

    Optimize for the next reader.

    Including (especially) future me, three months from now, who has forgotten everything and just wants to ship one fix.

  4. P/04

    Ship small, ship often.

    Tiny green CIs beat large red ones. A merged hundred-line PR is worth ten thousand-line drafts in a stale branch.
